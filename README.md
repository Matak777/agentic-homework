# Taskboard: исправление issue #7

Готовый технический пример домашней работы: исходники, тесты, два цикла спецификации и реализации, скриншот и четыре красных прогона.

## Запуск

Проверено с Node.js 24.19.0 и npm 12.2.3. Для зависимостей используется исходный `package-lock.json`.

```sh
npm ci
npm test
npm run build
npm run dev
```

Откройте адрес, который напечатает Vite. Изначально видны две задачи, счётчик «Открытых: 1». Пустое переименование сохраняет прежнее название и показывает ошибку. Пробельные символы и U+200B по краям обрезаются; старые пустые записи скрыты во всех фильтрах.

## Что подготовлено

- `SPEC.md` — итоговая спецификация с пятью разделами; начальная версия сохранена в `evidence/SPEC-v1.md`.
- `src/tasks.ts`, `src/App.tsx` — изменения реализации отдельным агентом.
- `src/tasks.test.ts` — два исходных теста без изменений.
- `src/acceptance.test.ts`, `src/zero-width.test.ts` — приёмочные проверки для двух этапов задания.
- `INTERVENTIONS.md`, `REPORT.md`, `REFLECTION.md` — журнал, отчёт и пять строк разбора.
- `evidence/app.png` — итоговый снимок работающего приложения.
- `evidence/red.txt` — четыре настоящих красных прогона (а), (б), (в), (г), изменения и зелёные восстановления.
- `evidence/green.txt`, `evidence/build.txt` — итоговые проверки; остальные логи сохраняют порядок двух циклов.
- `evidence/before-agent-v1.json`, `evidence/before-agent-v2.json` — время и хеши исходных версий требований и тестов; последующие правки текста отмечены отдельно.
- `evidence/diff-stat.txt`, `evidence/implementation-final.patch` — статистика изменений и патч реализации относительно чистого стартера.

Технический итог: **41 тест проходит, сборка успешна, четыре мутации обнаружены**. В исходных данных запись 3 сохранена: она исключается при чтении, а не удаляется.

## Повтор для защиты

```sh
python3 scripts/check-mutation.py а
```

Вместо `а` можно выбрать `б`, `в` или `г`. Скрипт проверит начальную зелёную версию, внесёт одну временную поломку, покажет упавшие тесты, восстановит исходник и подтвердит зелёный результат. Повтор сохраняется в `evidence/red-replay.txt`, исторический `red.txt` остаётся без изменений.

Зелёный прогон подтверждает только перечисленные в тестах случаи. Красные прогоны доказывают, что конкретные нарушения действительно обнаруживаются; варианты пробельных символов расширяют проверку за пределы исходного примера.
